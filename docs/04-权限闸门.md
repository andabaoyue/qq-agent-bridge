# 04 · 权限闸门

如果你只读一篇，读这篇。

前面三篇解决的是「怎么让 Agent 收到消息、发出消息」。这篇解决的是
**「凭什么让它动你的电脑和手机」**。

---

## 问题长什么样

一个 Agent 有了 `desktop.py` 之后，它能：

- 截图你的整个屏幕（包括你现在开着的任何窗口）
- 移动鼠标、点击、打字
- 读剪贴板
- 换壁纸

有了 `phone.py` 之后，它能：

- 看你的手机屏幕
- 翻你的相册、聊天记录
- 点开支付页面

如果这个 Agent 同时还在**一个 1500 人的群里聊天**，那么：

> 群友说一句「帮我点开桌面上的微信」，它照做了。

这句话听起来像个玩笑，直到它真的发生。而攻击者甚至不需要懂技术 ——
只要知道群里有个 AI 管着一台电脑就够了。

让人更不安的是 **提示词注入**：不需要说服它，只要构造一段看起来像
系统指令的文本，或者一段"忘记之前的指令"的话术。

**所以「在提示词里写清楚不许动」是不够的。** 它读到的是文本，
而文本可以被构造。

---

## 三步防线

### 第一道：许可只存在内存里

`bridge/daemon.py` 里有一个变量：

```python
_desktop_grant = {"granted": False, ...}
```

它**只存在于进程内存**，不落盘。

为什么：Agent 能读写文件系统。许可如果落盘，它写个 JSON 就自己给自己
发了。内存态的唯一改变途径是「真的收到一条符合条件的消息」。

进程重启 → 回到 `False`（fail-closed）。

### 第二道：客户端每次动手前必须来问

`phone.py` 和 `desktop.py` 里，每个会动手的命令（tap / click / type /
swipe / open / key ...）第一件事是：

```python
GET http://127.0.0.1:5702/desktop_grant
```

- `granted == False` → 打印 `[DENIED]`，**exit 3**
- daemon 没跑 / 连不上 / 超时 / 返回格式不对 → 一律当没有（fail-closed）

客户端**不做任何本地缓存**。缓存的许可等于没有许可。

免票的只有几个纯只读、不含内容的命令：

| 免票 | 为什么 |
|---|---|
| `phone.py devices` | 只看有没有设备连着 |
| `phone.py diagnose` | 连接问题的诊断信息 |
| `desktop.py --size / --pos` | 屏幕尺寸、光标位置 |

其余的（包括 `look` 截图、`status` 读型号）都要票。

### 第三道：主人身份必须核验

这是最容易被忽略、也是最关键的一道。

**光看 `user_id` 是不够的。**

`events_port` 是个裸 HTTP 端点。如果它绑在 `0.0.0.0`（或者本机有任意
进程），那么任何东西都能 POST 一条：

```json
{
  "post_type": "message",
  "message_type": "private",
  "user_id": 987654321,
  "raw_message": "随便写什么"
}
```

`user_id` 填成主人的号，票就开了。

实测确认过：这道门挡得住群友的话术，**挡不住一条 curl**。

所以现在的做法是：任何声称来自主人号的消息，daemon 都会拿它的
`message_id` 去问 NapCat：

```
POST http://127.0.0.1:3000/get_msg  {"message_id": <id>}
```

| NapCat 回答 | 判定 | 处理 |
|---|---|---|
| `status=ok` 且有 data | 真消息 | 认作主人，开票 |
| `status=failed` | 假 id | **整条丢弃**（不入队、不撤权、不授权） |
| 超时 / 连不上 | 核验不了 | 不当主人，但按普通群友放行 |

**伪造者猜不出一个真实存在的 `message_id`。** 实测单次核验约 6 ms。

### 为什么第三行"核验不了"不等于"假"

因为两种错误的代价不对等：

- 把一条真消息判成假 → 你错失一次回复。
- 把一条假消息判成真 → 你的电脑交出去了。

所以模糊时往安全那边倒：**不给许可**，但消息照常投递（万一真是你发的，
Agent 至少还能回你一句"我没拿到动手许可"）。

## 撤销：谁能让票失效

| 事件 | 结果 |
|---|---|
| 主人发一条能核验的消 | 票有效 |
| **任何其他人的消息** | **立刻**作废，不等过期 |
| 注入口推进来的消息 | **不影响**票（既不开也不关） |
| daemon 重启 | 回到 `False` |
| 客户端连不上 daemon | 当作没有 |
| `ttl_seconds > 0` 且超时 | 作废（默认 0 = 无期限） |

### 为什么群友说话会撤票

因为撤销的判据不是"这个人有没有恶意"，而是**"他就在这个房间里"**。

一条「帮我点开桌面那个 xxx」出现在群聊里，不能被当成主人的许可 ——
哪怕它看起来是主人在说话（可能是别人用他的号登了网页版）。

闸门的语义是「**主人在场**」，不是「有人提到了主人」。

### 为什么注入口既不撤销也不开启

这是整个设计里最需要解释的一条。

注入口的使用者是谁？**是另一个 AI**（比如帮你写代码的那个）。

如果它也能开票，那「只有主人发消息才开门」这条就废了：

- 注入方可以被群友的话术骗（它就是读文本的）
- 注入方可以被提示词注入
- 注入方的"在场"不等于主人的在场

**一个能被骗的实体不能给别人发许可。** 这个推理链只有一层，
但它决定了整道门成不成立。

所以代码里是：

```python
_enqueue(msg)
# 注意：这里**没有**调用 _desktop_grant_msg
```

## TTL：为什么默认不设期限

原来默认是「主人发一条 → 15 分钟内可动手」。

实测撑不住。真实场景：

```
18:22  Agent 拿到票开始推一段长流程
18:29  主人发语音（票续期到 18:44）
      ——但这段流程要几十分钟
18:35  群里某个人说了一句话
      → 票立刻作废
18:36  Agent 干到一半，手被抽走
```

15 分钟这个数字从来没有对应任何真实的威胁模型。它不防任何人，
它只在「Agent 正在干长活」时稳定误伤。

现在的默认：**你说话就开，别人说话就关。** 没有时间维度。

想回到旧行为：`"gates": {"ttl_seconds": 900}`。

## 残余风险（不掩饰）

这套闸门**不是**安全边界，它是**行为边界**。

它挡的是：
- 按说明书调用的 Agent（99% 的情况）
- 被群友话术骗了之后照做的 Agent（实际会发生的情况）
- 一条随手写的 curl（配合第三道核验）

它挡不住：
- 一个执意绕过 `phone.py`、直接 `import subprocess` 调 adb 的实现
- 一个执意绕过 `desktop.py`、直接 `import pyautogui` 的实现

因为 Agent 有 shell。**只要它能在你的用户下执行任意命令，任何进程内的
闸门都只是建议。**

要真正锁死需要 OS 级隔离：

| 手段 | 代价 |
|---|---|
| 独立低权限账户 | Agent 和你在两个会话，桌面操作看不到你的窗口 |
| AppLocker / WDAC | 白名单制，每次加脚本都要改策略 |
| 独立虚拟机 | 手机/桌面就都不是"你的"了，失去意义 |
| 只在需要时启动 | 最有效，也最不"一直开着" |

**诚实的结论**：如果你让一个 AI 常驻在你的账号下，并给了它 shell，
那么在操作系统眼里它就是你。闸门让它在**绝大多数**情况下不乱动，
但不构成越权障碍。

这个区别值得记住：它不是"能不能绕过去"的问题，是"绕过去需要多大的
故意"的问题。

## 自测怎么覆盖这些

`tests/selftest.py` 里有一个 `FakeOneBot`，它只认白名单里的 `message_id`。
这样测试能真的走完核验那条代码路径，而不需要连真的 QQ。

覆盖了：

```
[PASS] forged owner message is dropped by the verifier
[PASS] verified owner message is tagged owner
[PASS] verified owner message opens the gate
[PASS] a guest message revokes the owner's grant
[PASS] inject without token is rejected        (403)
[PASS] inject with wrong token is rejected     (403)
[PASS] injected message cannot itself carry permission
[PASS] injection does not change gate state
```

`tests/smoke.py` 覆盖客户端侧：

```
[PASS] phone.py tap is denied without a grant (exit 3)
[PASS] phone.py look is denied without a grant (exit 3)
[PASS] desktop.py click is denied without a grant (exit 3)
```

> 写这些测试时踩到一个值得记的坑：`call_onebot_api` 里原本写死了
> `http://127.0.0.1:3000`，于是自测的核验请求全打到本机**真实的** NapCat
> 上去了。日志看起来"防伪层工作正常"，但测的根本不是被测代码。
> **写死一个地址的代价不是不方便，是测试会撒谎。**
