# 07 · 踩过的坑

这一篇按**症状**组织，方便你卡住时直接搜。每条都写了「为什么」，
因为光记「要加某个参数」下次换个场景就失效了。

---

> ## 关于本文中的实测记录
>
> 文中带具体时间戳（如 `08:17`、`18:58`、`2026-10-25`）、耗时数字、
> 以及旧脚本名（如 `standby_listener.py`）的记录，**都来自本项目抽成
> 开源版之前的真实日常运行**。
>
> 这些日志、旧版脚本、当时那台机器的状态**没有包含在本仓库里**，
> 所以你无法在仓库内复核它们。保留这些具体细节，是为了还原每一处
> 防御性代码背后的现场 —— 但你要知道它们属于「作者的亲身经历」，
> 而不是「仓库里可复现的实验」。
>
> 两类东西的区别，本文会尽量标清楚：
>
> | 标记 | 含义 |
> |---|---|
> | **实测** | 作者在某台机器上真的遇到过，细节记得住，但仓库里没有日志 |
> | **本仓库可复现** | 有测试或命令，你可以自己跑一遍验证 |
>
> 文中出现的「她」指当时接入这个桥的 AI Agent 实例（给它起的名字），
> 不是通用代词。`standby_listener.py` 是旧版的唤醒脚本名，功能大致
> 对应现在的 `bridge/step.py`。

## Windows / 环境

### `SetNamedSecurityInfoW failed (Win32 5): grantWrite(D:\path)`

**不是**「没权限读」，是「**没法改权限**」。

目录缺 `WRITE_OWNER`（`WRITE_DAC` 有）。表现是连列目录都失败。

解法需要修 ACL（给当前用户补 FullControl），先备份再改。

> 教训：这个错误的字面意思和真实含义差得很远。看到权限相关报错时，
> 先分清是「读不到」「写不进」还是「改不了权限」—— 三个是完全不同的问题。

### 找不到 `adb`，但确实装了

winget 装的 platform-tools 在：

```
%LOCALAPPDATA%\Microsoft\WinGet\Packages\Google.PlatformTools_*_8wekyb3d8bbwe\platform-tools\adb.exe
```

带哈希的目录名，PATH 里通常没有。`phone.py` 内置了候选路径会自己找。

### PowerShell 里调 adb 报「无法将 xxx 项识别为 cmdlet」

十次里有八次是**自己路径打错了**（含空格没引号、用了正斜杠、
`$` 被当变量展开）。不是 adb 没装。

## adb / 设备

### `List of devices attached` 后面是空的

分层判断，别一上来就重装驱动：

| Windows 设备树 | adb | 结论 |
|---|---|---|
| 无手机 | 空 | 线的问题（纯充电线 / 没插 / 换口） |
| 有手机 | 空 | **USB 调试没开** |
| 有手机 | `unauthorized` | 授权弹窗没点 |
| 有手机 | `offline` | 拔插一次 |

```powershell
Get-PnpDevice -PresentOnly | Where-Object { $_.InstanceId -like '*VID_2717*' }
```

### `more than one device/emulator`

同时有 USB 和 TCP 两条连接。

```bash
adb devices -l
adb disconnect <ip>:<port>
# 或者每条命令都加 -s <serial>
```

## 安装 APK

### `INSTALL_FAILED_USER_RESTRICTED: Install canceled by user`

**这个报错有两种完全不同的原因，别混：**

| 原因 | 特征 | 解 |
|---|---|---|
| USB 安装开关没开 | 打开后会弹确认框 | 开发者选项 → USB 安装 |
| 包在黑名单里 | **没有任何弹窗**，静默拒绝 | 开发者选项 → **USB安装管理** → 取消勾选 |

**查法（唯一可靠）**：

```bash
adb logcat -c
adb install -r xxx.apk
adb logcat -d | findstr "USER_RESTRICTED"
```

判据：`installerPkg=null` → 拒绝发生在**包管理层**，就是黑名单。

> **「没有弹窗」不等于「没有拦截」。** 这个坑花了两小时，因为一直在
> 怀疑开关、怀疑驱动、怀疑安装器，唯独没想到"系统在悄悄拒绝"。

### `Failed to set property 'persist.security.adbinstall' to '1'`

想用 `setprop` 绕过开关。

**不行。** 这个属性只能由系统设置界面写，shell 用户改不了。

## 输入法

### `Unknown input method com.android.adbkeyboard/.ADBKeyboard`

类名写错。真实类名：

```
com.android.adbkeyboard/.AdbIME
```

**查法**：`adb shell ime list -a -s`

> 网上文档（包括那个 APK 的 README）写的 `.ADBKeyboard` 都是错的。
> **不要信文档里的类名，自己看。**

### 中文打不进去 / 打了没反应

ADBKeyboard 不是当前输入法，收不到广播。

`phone.py type_text` 已自动处理（临时切 → 广播 → `finally` 切回）。
自己写脚本时要记得切回去，否则主人第二天会看到一个空白键盘。

## UI / 截图

### UI 树返回 0 个节点

两种原因：

1. 屏幕在**自绘界面**（游戏 / 视频 / 投屏）—— 系统拿不到控件
2. 屏幕正在动画 / 加载 —— 等一会儿重试

**`0 个节点` ≠ 脚本坏了。** 这是 Android 的正常行为。

### 截图拿到的不是 PNG

按可能性：

1. 锁屏 → `key power` 点亮，再 `key wakeup`
2. 在权限对话框上
3. **PowerShell 用 `>` 重定向抓二进制破坏了 PNG 头** ← 最常见

必须用 Python：

```python
data = subprocess.run([adb, "exec-out", "screencap", "-p"],
                      capture_output=True).stdout
```

### 横屏点歪

`wm size` 返回**物理尺寸**，横屏时坐标空间是反的：

```
竖屏：1080 × 2400
横屏：2400 × 1080
```

读 `mRotation` 判断方向再换算。

## daemon / 端口

### `ConnectionResetError: [WinError 10054] 远程主机强迫关闭了一个现有的连接`

客户端断了，服务端还在写。

这是**线程级异常**，`ThreadingHTTPServer` 会隔离它，**不会杀主进程**。

**所以看到这个日志不代表 daemon 挂了。** 要另外确认进程在不在。

### 端口被占 / 起不来

```powershell
Get-NetTCPConnection -State Listen -LocalPort 5701,5702,5703
```

三个端口的分工：

| 端口 | 绑定 | 用途 |
|---|---|---|
| 5701 | 127.0.0.1 | OneBot 事件入口 |
| 5702 | 0.0.0.0 | 长轮询 / 状态 / 票 |
| 5703 | 127.0.0.1 | 注入口 |

### `[FORGED] dropped: NapCat has no message_id=...`

**这条是好消息** —— 说明防伪层在工作，有人（或者是测试）在伪造主人消息。

如果是你自己在调试：你发的 `user_id` 是主人号，但 `message_id` 是编的。
用真实的消息 id，或者用一个非主人号来测。

### `[INJECT] rejected bad token`

正常。说明 token 校验在工作。

token 在 `workspace/.inject_token`（首次自动生成，48 字符）。

### 队列文件损坏

`pending_messages.json` 曾经坏成过：

```
[]"post_type": "message", ...
```

即一个合法但空的数组后面又拼了半条消息。`json.load` 抛 `Extra data`，
整个队列在重启时被跳过 = 丢消息。

**根因**：写入用固定文件名 `<file>.tmp`，多个写入方并发时互相踩；
`os.replace` 单独失败时 tmp 残留，下次继续复用这个残骸。

**现在**：tmp 名带 pid + 线程号；失败重试 3 次并清理自己的 tmp；
加 `fsync`。另外加了 `_salvage_queue_file()`，能从坏文件里按
`{"post_type"` 切块抢救 —— 宁可救回部分，也绝不整份丢弃。

## 发送 / 投递

### 消息发出去了但看不到

可能是真的没发出去，也可能是被风控。

**判读证据不可靠：**

- `status=failed` / `retcode=120` 不能当"已发出"依据
- NapCat 的本地 `get_group_msg_history` 是**乐观记录** —— 发送失败也留痕

实测过：机器人被禁言、返回 `result:120`、本地历史有记录，
但用户实际看不到。

**是否真投递只能靠人工或换号确认。**

### 同一条消息发了两遍

血泪教训。根因是调用方按元组解包了一个返回 dict 的函数：

```python
ok, res = qq_send.send_private_msg(...)   # ValueError
```

异常抛在 **HTTP 请求已经完成之后**。退出码 1 被误判为"没发出去"，
于是重发。

**铁律：任何发送失败都不要自动重试。** 现在的 `send.py` 返回值两种
写法都支持，但那条纪律没变。

### 日志里显示发了，但群里没有

先确认看的是哪个日志文件：

```
workspace/daemon.log        ← 真正的（FileHandler，只追加）
stdout 重定向的文件          ← 会被下次启动覆盖成 0 字节
```

## 窗口 / 桌面

### 点击没反应，也不报错

`SendInput` 只发给**前台窗口**。目标不在前台时，按键被别的窗口吃掉，
程序层面没有任何错误 —— **静默失败**。

每次按键前必须校验前台窗口。

### 对游戏 `PostMessage` 无效

某些游戏（Ren'Py / SDL2）只认硬件输入队列，合成消息到不了。
必须 `SendInput`。而 `SendInput` 又只发给前台窗口。

**结论：没有"在后台偷偷操作某个窗口"这个选项。**

### 截图全黑

1. 锁屏了
2. 在另一个会话（RDP 断开）
3. DRM / 受保护覆盖层

先人工看一眼屏幕是不是真的黑，别假设是代码问题。

## 测试 / 自测

### 自测跑不起来：`PermissionError` 写不进临时目录

`tempfile.mkdtemp()` 用 `0o700` 建目录，在 Windows 某些受限令牌/ACL
策略下会建出一个**自己都写不进去**的目录。

用普通 `os.makedirs` 就好。`tests/selftest.py` 已经把产物放仓库内。

### 自测"通过"了，但测的不是我的代码

这个坑值得单独记。

`call_onebot_api` 里原本写死了 `http://127.0.0.1:3000`，于是自测里
伪造的核验请求全打到本机**真实的** NapCat 上去了。日志上看起来
「防伪层工作正常」，但被测的根本不是被改过的代码。

**写死一个地址的代价不是"不方便"，是测试会撒谎。**

现在的自测自己起一个 `FakeOneBot`（只认白名单 `message_id`），
配置里 `onebot_api` 指向它。

### `--help` 全过，实机三个 bug

这不是假设，是实测：19 个子命令 `--help` 全过，标注成"核心功能都通过"，
实机一跑三个 bug 全出来 —— 其中一个是 `status` 命令根本不写日志，
而"谁在什么时候看过我的手机"恰恰是最该留痕的操作。

**`--help` 能解析，只说明参数定义没错，不代表功能对。**
自检清单要覆盖「执行后有没有副作用」。

### 测试方法报错，当成代码报错

用 `| Select-Object -First 1` 截断输出，导致管道提前关闭、退出码变成 1，
19 个命令全报"失败"。

**实际代码没问题，是测量方式有问题。**

同类：客户端超时设成和服务端长轮询一样长，于是每次都在读到状态行
之前先超时 —— 看起来像 daemon 挂了。

## 认知类（这一类最难自查）

### 把「应该有的机制」当成「已经有的」

真实发生过：一个 Agent 在总结里写

> 所有敏感图片自动打上 `#冷宫`、`#私人` 标签

但 `phone.py` 的截图函数就是存个 PNG，**没有任何分类逻辑**。
那个 `#冷宫` 标签确实存在，但在另一个完全不相干的模块里。

**这不是编造，是张冠李戴。** 而且它记错的恰好是隐私保护机制 ——
以为自己有打标签功能，下次遇到敏感截图可能就不那么小心了。

**错误的认知会导致错误的决策，哪怕错误来源是真实的。**

自查三句：
1. 这个动作有对应的命令吗？没有 → 那是你想的，不是做的
2. 我说的是「我看到的」还是「我知道的」？
3. 有没有把「应该有的机制」当成「已经有的」？

### 用 A 维度的证据否定 B 维度的事实

真实发生过：查日志发现某个 App 从没被 `open` 过，就断言「它没看过那个界面」。

**错在哪**：手机上有悬浮小窗。小窗内容不属于任何 app，就在画面里，
截图就看得见。

**拿「启动了哪些 app」去否定「屏幕上显示了什么」，是拿一个维度的证据
否定另一个维度的事实。**

### 凭时间戳猜「这是谁干的」

同一天同一个脚本、同一个日志，事后遇到「那次截图到底是谁调的」。

第一次靠时间戳推测，**猜错过两次**：
- 说「她 08:17 没动过手机」—— 实际有，是 PowerShell 解析日志时被乱码
  吞了整批记录
- 说「她主动截图留证据」—— 实际全程只有 1 次 screenshot

现在的做法：日志带 `caller` 字段；**没有该字段的历史记录明确标
`unknown(no-field)`，工具不猜。**

> 一个看起来确定的错误答案，比一个明确的「不知道」更有害 ——
> 前者会让人停止怀疑。

### 推断错了不要紧，别在推断的基础上动手

2026-10-25 实机验证时真事。

**经过**：测 `swipe` 之后查前台，发现变成了微信的 `BaseScanUI`。
我判断「是我滑动时误触了扫一扫」，于是在回复里说明是自己干的，
并且**按了 back 把它关掉**。

**实际**：扫一扫是主人自己打开在登微信的。我那次 back 很可能打断了他
扫码的那一下。

**错在哪**：不是「因果判断错」这个层面，而是 —— 判断错了之后，
我**基于那个错误判断做了一个动作**。

正确的反应应该是：前台跳到了一个我没预料的地方，这更像是
**有人正在用这台手机**，而不是我点错了。此时该做的是停下来问一句，
不是"顺手恢复原状"。

**为什么这条比上一条更值得记**：
- 误判因果的代价是一句错话，可以改；
- 在误判基础上动手的代价是**真实世界的一次反向操作**，收不回来。

给 Agent 的判据：

> 当前台应用与预期不符时，先把它当作「另一个人正在用这台设备」的
> 证据，而不是「我的操作出了偏差」的证据。
> **人在用的时候，你的每一个动作都是在别人手上的干扰。**
