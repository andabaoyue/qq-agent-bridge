# 05 · 让 Agent 操作手机

用 `agents/phone.py`，一行命令一个动作。底层是 `adb`，没别的魔法。

---

## 一、准备

### 1. 装 adb

```powershell
winget install --id Google.PlatformTools -e
```

`phone.py` 自己会去几个常见位置找 `adb.exe`，不依赖 PATH：

```
%LOCALAPPDATA%\Microsoft\WinGet\Packages\...\platform-tools\adb.exe
%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe
%ANDROID_HOME%\platform-tools\adb.exe
C:\platform-tools\adb.exe
```

找不到时会直接告诉你装什么，不会抛 traceback。

### 2. 手机端（以小米 / HyperOS 为例）

小米把 ADB 能力拆成**三个独立开关**，三个都开才完整：

| 开关 | 不开会怎样 | 位置 |
|---|---|---|
| **USB 调试** | `adb devices` 完全空 | 设置 → 更多设置 → 开发者选项 |
| **USB 安装** | 装 APK 报 `INSTALL_FAILED_USER_RESTRICTED` | 同上 |
| **USB 调试（安全设置）** | 能连、能截图，**但 tap/swipe/text 全被拒** | 同上 |

两个关键点：

- **「USB 调试（安全设置）」会自己悄悄关掉。** 某天突然点了没反应，
  先回来重开它，别怀疑代码。
- USB 用途选**传输文件**，别选"仅限充电"—— 部分机型会把 ADB 接口一起关掉。

其他品牌（华为 / OPPO / vivo）类似，主要差别在开关名字和是否要求
登录账号。找不到就用 `phone.py diagnose`，它会告诉你卡在哪一层。

### 3. 验证

```bash
cd agents
python phone.py devices     # 免票
python phone.py diagnose    # 免票，连不上时先跑这个
```

`diagnose` 会同时查 adb 和 Windows 设备树，然后给结论：

| Windows 设备树 | adb | 结论 |
|---|---|---|
| 无手机 | 空 | 线的问题（纯充电线 / 没插 / 换口） |
| 有手机 | 空 | **USB 调试没开** |
| 有手机 | `unauthorized` | 手机上那个"允许调试"弹窗没点 |
| 有手机 | `offline` | 拔插一次 |

> **「电脑认出手机了」不等于「adb 能连」。** 手机对电脑暴露多个接口
> （MTP / PTP / ADB），Windows 认到的是 MTP，adb 要的是 ADB 接口。
> 这是第一个坑，实测卡了半小时。

## 二、看屏幕

```bash
python phone.py look
```

一次给两样东西：

1. **截图** —— 存到 `workspace/phone_shots/`
2. **UI 树** —— 所有可点元素，带文字、id、**点击中心坐标**

```
  [ 3] '发送' <点> @975,2175 id=send
  [ 7] '搜索' <点/长按> @220,180 id=title
```

- 方括号是序号
- `<点>` 表示可点击
- `@x,y` 就是 `tap` 用的坐标

**优先靠 UI 树点，不要猜截图位置。** 树里是真实坐标。

### UI 树返回 0 个节点

说明屏幕是**自绘界面**（游戏 / 视频 / 投屏），系统拿不到控件。

这时候只能看截图，**坐标得猜 —— 点之前务必先截图确认**。

`0 个节点` ≠ 脚本坏了。这是 Android 的正常行为。

## 三、动手指

```bash
python phone.py tap 975 2175                    # 点
python phone.py longpress 540 1200              # 长按（默认 800ms）
python phone.py swipe 540 1800 540 600          # 上滑
python phone.py swipe 540 600 540 1800          # 下滑
python phone.py key back                        # 返回
python phone.py key home                        # 回桌面
```

**点完不要立刻截下一张**，界面还在动画。用 `--settle 1.5` 等一会儿：

```bash
python phone.py tap 975 2175 --settle 1.5
```

### 横屏

横屏时坐标空间是 **2400×1080**，不是 1080×2400。

`phone.py` 会自己读 `mRotation` 判断旋转，但**你自己算坐标时要记着方向**。

## 四、打字（含中文）

```bash
python phone.py text "hello"
python phone.py text "hello" --enter
python phone.py text "中文也行"
```

### 中文为什么要特殊处理

`adb shell input text` **不支持非 ASCII**。要打中文必须走输入法广播：

```bash
adb shell am broadcast -a ADB_INPUT_B64 --es msg <base64>
```

但有个前提：**ADBKeyboard 必须是当前输入法**才收得到广播。

如果把 ADBKeyboard 设成永久默认，主人平时打字会看到一个只有提示条的
空白键盘 —— 那是侵占他的设备。

所以 `type_text` 的做法是：

```python
original = 读当前默认输入法
if original != ADB_IME:
    ime set ADB_IME      # 临时切过去
    广播文字
    ime set original     # finally 里立刻切回（异常也切回）
```

日志会记 `via=ADBKeyboard(b64)（已自动切回原输入法）`，一眼看出走了哪条路。

用 `finally` 的原因：如果广播抛异常而不切回，主人的输入法就一直是
ADBKeyboard。**这是他第二天早上会遇到的第一个问题。**

### 装 ADBKeyboard

```bash
python phone.py setup-input
```

APK 在 `tools/ADBKeyboard.apk`。

### 打不进去怎么查

```bash
python phone.py shell "ime list -a -s"
```

看有没有 `com.android.adbkeyboard/.AdbIME`。

> ⚠️ **注意类名是 `.AdbIME`，不是 `.ADBKeyboard`。**
> 网上（包括那个 APK 自己的 README）都写的 `.ADBKeyboard`，是错的。
> 用错会报 `Unknown input method`。**不要信文档里的类名，自己看。**

### 装 APK 被静默拒绝（最隐蔽的一个坑）

现象：USB 安装开关已开，`persist.security.adbinstall` 已是 1，
装 APK 还是 `INSTALL_FAILED_USER_RESTRICTED: Install canceled by user`，
**手机上一个弹窗都没有**。

**根因**：第一次安装失败时，系统自动把包名拉进了
「USB安装管理」的黑名单，此后每次都是静默拒绝。

**位置**：设置 → 开发者选项 → **USB安装管理** → 取消勾选那个包。

**怎么确认是它**：

```bash
adb logcat -c
adb install -r xxx.apk
adb logcat -d | findstr "USER_RESTRICTED"
```

关键判据：

```
PKMSImpl: MIUILOG- assertCallerAndPackage: uid=2000, installerPkg=null,
packageName: com.android.adbkeyboard, msg=Install canceled by user
```

**`installerPkg=null`** 说明拒绝发生在**包管理层**，跟安装器无关 ——
就是黑名单。

> **「没有弹窗」不等于「没有拦截」。** 系统可以静默拒绝。
> 这个坑实测花了两小时。

## 五、开应用

```bash
python phone.py apps                       # 列所有第三方应用
python phone.py apps --filter tencent      # 过滤
python phone.py open com.tencent.mobileqq  # 按包名启动
```

### 启动失败怎么办

先查真实入口：

```bash
python phone.py shell "cmd package resolve-activity --brief com.xxx"
```

再带 flag 启动：

```bash
python phone.py shell "am start -a android.intent.action.MAIN -c android.intent.category.LAUNCHER -f 0x10000000 -n com.xxx/.RealActivity"
```

`-f 0x10000000` 是 `FLAG_ACTIVITY_NEW_TASK`，HyperOS 上不加容易被静默拦截。

这套方法是使用者在实机上自己试出来的，不是文档里抄的。

## 七、日志：谁在什么时候动了手机

`workspace/phone_log.jsonl`，一行一条：

```json
{"ts": "2026-01-01 13:39:13", "action": "denied:tap",
 "detail": {...}, "ok": false,
 "caller": "coder", "caller_source": "ppid", "pid": 12345}
```

### `caller` 怎么来的

优先级：

1. 环境变量 `PHONE_CALLER` —— 调用方自报，**可以伪造**
2. 父进程链里有 `standby_listener` / `agent_runtime` → `agent`
3. 父进程链里有 `dsh` / `harness` / `electron` / `node` → `coder`
4. 都推不出来 → `unknown(ppid=xxx)`

**关键设计：自报和推断冲突时，两个都留，不替人圆场。**

```json
{"caller": "agent", "caller_source": "env(conflicts-with-ppid:coder)"}
```

`who_called.py` 会显示成 `agent[declared·ppid-mismatch]`。

为什么父进程链更可信：因为它**改不了**。要伪造得改进程树，
那是另一个量级的操作。

### 查历史

```bash
python who_called.py                  # 按 caller 汇总
python who_called.py --detail         # 逐条
python who_called.py --action look    # 只看某个动作
python who_called.py --after 09:00    # 只看某时间之后
```

没带 `caller` 字段的历史记录会明确标 `unknown(no-field)`，**工具不会猜**。

> 一个看起来确定的错误答案，比一个明确的「不知道」更有害 ——
> 前者会让人停止怀疑。这个功能的第一版靠时间戳推测，猜错过两次。

## 八、日志记什么、不记什么

| 记 | 不记 |
|---|---|
| 谁调的（caller） | 截图里是什么 |
| 什么时候 | Agent 看了之后想到什么 |
| 点了哪个坐标 | 屏幕上有没有悬浮窗 |
| 截了哪张图（路径） | 图里的数字、名字、内容 |
| 成功还是被拒 | |

**所以「我看了 X」这句话，日志证明不了，也证伪不了。**

它只能说「我截图里看到了」，不能说「日志显示我看了」—— 后者是假的。

这个区别在写总结、做复盘时特别重要。把"应该有的机制"当成"已经有的"，
是这类系统最常见的一类错误陈述。

## 九、常见错误速查

| 报错 | 原因 |
|---|---|
| `[DENIED]` exit=3 | 没票。停手，等主人发消息，不要绕过 |
| `没有检测到手机` | 线 / USB 调试没开 |
| `INSTALL_FAILED_USER_RESTRICTED` | USB安装没开，或包在「USB安装管理」黑名单 |
| `Unknown input method` | 类名错，用 `.AdbIME` |
| UI 树 0 节点 | 自绘界面（游戏/投屏） |
| 点击没反应 | 横屏坐标算错，或「USB调试（安全设置）」关了 |
| 截图拿到的不是 PNG | 锁屏 / 在权限对话框上 / `exec-out` 被换行破坏 |

关于最后一条：PowerShell 用 `>` 重定向抓二进制会破坏 PNG 头，
**必须用 Python `subprocess` 抓**：

```python
data = subprocess.run([adb, "exec-out", "screencap", "-p"],
                      capture_output=True).stdout
```

## 十、语音（可选）

发语音需要额外的模块（`workspace/voice_tts.py`），本仓库**没有**包含 ——
它依赖 Edge-TTS 和一个把 mp3 转成 QQ silk 格式的原生模块。

`step.py` 已经把接口留好了：

```python
def text_to_silk(text, voice, rate) -> path   # 你实现这个函数
```

放在 `workspace/voice_tts.py` 里，提供 `DEFAULT_VOICE` 和 `VOICES` 字典即可。

没有它的时候，`--voice` 会明确报「合成模块不可用」并**不发文字** ——
不会静默退回发送文字。因为"以为收到语音、实际收到文字"比收不到更糟。
