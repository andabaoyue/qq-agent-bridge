# 未在实机上验证的部分

写这份文件的原因：**把"没验证"和"验证过"混在一起说，是这类文档最
常见的失真方式。** 读者会默认表格里列出来的都测过，故障时就会往错
方向查。

下面这些在本仓库的开发过程中**没有在真设备上跑过**，原因和风险都写了。
如果你要依赖它们，请先自己验一遍。

---

## 1. `phone.py wireless` —— 无线调试

**没测，且不打算测。**

原因：Android 11+ 的「无线调试」需要手机弹窗里的一次性配对码，
每次打开弹窗都不同。这要求一个人在手机旁边看着屏幕念数字——
不是能自动化的东西，而且测完还会把手机的调试方式切到 TCP。

**它的风险在前面，不在代码里**：切到无线调试后，USB 那条连接会断。
如果之后无线连不上，手机会进入「连不上也回不去」的状态，
需要重新插线。测试本身没有收益（用 USB 已经能跑完整套），
只有副作用。

**代码路径**：`--pair IP:端口:配对码` → `adb pair`；不带参数 →
读 Wi-Fi IP → `adb tcpip` → `adb connect`。逻辑直白，失败时的
报错信息给得比较细（弹窗超时、不在同一 Wi-Fi、配对码抄错）。
未验证的是这些分支在真机上会不会给出正确的提示。

---

## 2. `phone.py setup-input` —— 装 ADBKeyboard

**没测，但风险已经查明，可以放心。**

看代码（`cmd_setup_input`）：

```python
if not _has_adb_keyboard(serial):
    out = adb("install", "-r", apk, ...)
...
adb("shell", "ime", "enable", ADB_IME, check=False)
```

- **已经装过 → 不会重装。** 先 `pm list packages` 查，装了就跳过
  `adb install`，只做 `ime enable`。所以「重装 APK」这个担心不成立。
- 唯一实际动作是 `ime enable`（把 ADBKeyboard 加进可用输入法列表，
  **不改默认输入法**）。

**这部分其实被间接验证过**：2026-10-25 的中文输入实测里，
`text` 能成功切到 `com.android.adbkeyboard/.AdbIME` 并广播，
说明这个输入法在系统里已经是启用状态、类名也是对的。

**未验证的分支**：全新设备上第一次 `adb install` 的那条路，
以及失败时「USB安装管理黑名单」的报错提示是否准确。
前者会真的改动设备状态，后者需要故意制造失败——都不值得为它制造环境。

## 3. `phone.py diagnose` 的失败分支

**只验证了"设备正常"这一条分支。**

`diagnose` 的价值全在**连不上的时候**给结论：

| Windows 设备树 | adb | 结论 |
|---|---|---|
| 无手机 | 空 | 线的问题 |
| 有手机 | 空 | USB 调试没开 |
| 有手机 | `unauthorized` | 授权弹窗没点 |
| 有手机 | `offline` | 拔插一次 |

2026-10-25 实测时设备是通的，它直接回了
「adb 已经能看到设备，直接跑 status 就行」——**只有这一句被验证了**。

要验证上面那张表，得故意拔线、故意关 USB 调试、故意不点授权弹窗。
每次都要人去动手机，而且要恢复原状。这是**可以手动做、但不该由
Agent 自己做的**测试：它需要改变真实设备的状态才能触发。

**如果你遇到连接问题**，那张表本身就是文档（见
[05-手机控制.md](05-手机控制.md) 第一节），可以先照着人工判断。

## 4. `desktop.py` 全部命令

**一行都没在真机上跑过。**

`--size` 和 `--pos` 在自测里跑过（免票的只读命令），
但截图、点击、打字、滚动、换壁纸这些**全部没有实机验证**。

原因很直接：这台机器上有人正在用。桌面操作会打断正在进行的任何事
（和手机那次的 `back` 一样），而它没有「先看一眼再说」的余地——
截图本身就可能是别人正在看的窗口。

**未验证清单**：

```
--shot  --windows  --focus  --click  --double  --right
--move  --drag     --scroll --type   --press   --hotkey  --wallpaper
```

`--size` / `--pos` / `--help` 是免票只读，且自测覆盖。

**代码来自一份在实际使用中验证过的实现**，但那验证发生在另一台机器、
另一份代码上。这个仓库里的 `desktop.py` 改过路径和配置来源，
改动很小但确实改过——所以严格来说，它是"未经本仓库验证"的状态。

---

## 关于「为什么不全测了」

不是偷懒，是**收益和风险不成比例**：

| 项目 | 测它的收益 | 它的风险 |
|---|---|---|
| `wireless` | 低（USB 已能跑全部） | 中（可能切断调试通道） |
| `setup-input` | 极低（已间接验证） | 低（但不为零） |
| `diagnose` 失败分支 | 中（错误信息质量） | 低（但要人反复动手机） |
| `desktop.py` | 高 | **高**（会打断正在用电脑的人） |

最后一项的风险不是"可能出错"，是"**成功了也会打扰**"。
桌面操作的性质是：它没有安全的旁观位置。
