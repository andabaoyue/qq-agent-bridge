# 02 · 配置

只有一个文件：`bridge/config.json`。源码里没有任何真实号码，全部从这里读。

## 最小可用配置

```json
{
  "bot_qq": 123456789,
  "owner_qq": 987654321
}
```

其余字段都有默认值。下面逐个说，**只有前两个是必填的**。

---

## 必填

### `bot_qq`
机器人自己的 QQ 号。用来识别 `[@you]` 和判断"这条是不是在跟我说话"。

### `owner_qq`
主人（你）的 QQ 号。**这是整套权限体系的核心。**

可以写一个数字，也可以写数组：

```json
"owner_qq": [987654321, 123123123]
```

只有这里列出的号，发消息才可能开动手许可。而且**光有号还不够** ——
那个号的 `message_id` 必须能在 NapCat 那里查到（见 04 篇）。

不填的话程序会直接拒绝启动。这不是可以偷懒的项：填不对，你要么什么
都不能干，要么谁都能干。

---

## 机器人名字

### `bot_names`
群里提到这些词，就算在叫它。

```json
"bot_names": ["小助手", "阿助", "assistant"]
```

不填 = 只有 @ 才算叫它。

这些词参与 `mention_only` 判定，所以别填太常见的词 ——
填个「机器人」，群里每句「这机器人好笨」都会把它叫起来。

---

## 端口

### `listen`

```json
"listen": {
  "events_host": "127.0.0.1",
  "events_port": 5701,
  "poll_host": "127.0.0.1",
  "poll_port": 5702,
  "inject_host": "127.0.0.1",
  "inject_port": 5703
}
```

| 字段 | 作用 | 建议 |
|---|---|---|
| `events_host/port` | NapCat 往这里 POST 消息 | **保持 127.0.0.1** |
| `poll_host/port` | Agent 长轮询这里 | **默认 127.0.0.1**，见下 |
| `inject_host/port` | 另一个进程/AI 往队列塞消息 | **必须 127.0.0.1** |

### 为什么 `events_host` 必须绑 127.0.0.1

NapCat 是主动 POST 到我们这里，所以它**不需要**对外监听。

绑 `0.0.0.0` 的后果实测过：同一网段的任何一台机器，只要知道端口，
就能直接伪造一条消息。而且请求体里 `user_id` 是自己写的 ——
想冒充谁就冒充谁。零鉴权的裸 HTTP 挡不住一条 `curl`。

daemon 里还有一层 `message_id` 核验兜底，但那是第二道锁，不是第一道。

### 为什么 `inject_port` 永远不能对外

注入口的能力是「往 Agent 的队列里塞一条消息」。如果它对外可达，
等于把写权限开出局域网。

即便只有本机可达，它也带 token，而且它**永远开不了动手许可**（见 04 篇）。

### 为什么 `poll_host` 默认也是 127.0.0.1

早期版本这里默认是 `0.0.0.0`，理由是"方便 Agent 跑在另一台机器上"。
这个默认值不对，原因是 5702 上的 `/wait_msg` 是**破坏性**接口：

```
GET /wait_msg  →  从队列里取走消息并出队
```

绑 `0.0.0.0` 意味着同网段任何一台机器都能：

1. **抢走你的 QQ 消息**（它取走了，你的 Agent 就收不到了）
2. 读 `GET /desktop_grant`，看到主人 QQ 号和许可状态
3. 反复取空队列，让你的 Agent 一直以为没有新消息

第 1 和第 3 条不是"信息泄露"，是**功能被劫持** —— 而且受害者不会看到
任何错误，只会觉得"机器人怎么不回我了"。

所以默认改成 `127.0.0.1`。真的需要跨机器时再显式改，并配合防火墙。

### `poll_host` 什么时候才需要 0.0.0.0

只有一种情况：Agent 跑在**另一台机器**上，而 daemon 在这台。


如果 Agent 也在这台机器上（绝大多数情况），改成 `127.0.0.1` 更好。

## 群过滤

### `group_filter`

```json
"group_filter": {
  "mode": "mention_only",
  "allow_groups": ["123456789"],
  "block_groups": ["987654321"],
  "question_keywords": ["请问", "怎么", "如何"]
}
```

### `mode` —— 三种

| 值 | 含义 | 什么时候用 |
|---|---|---|
| `mention_only` | 只回被点名的（默认） | **推荐起点** |
| `mention_or_question` | 点名 **或** 命中问句关键词 | 想让它在群里答疑 |
| `all` | `allow_groups` 里的每条都处理 | 只适合你完全信任的小群 |

「被点名」包括：`@` 它、正文提到 `bot_names`、有人引用回复它、
或者**主人本人**说话。

### 关于 `mention_or_question` 的代价

说清楚，因为这是最容易配错的一格。

`question_keywords` 里的词会被当成"有人在问问题"的信号。但群聊里
这类词密度极高：「今天吃什么」「怎么还没到」「有没有人」全都命中。

实测历史（原版配置用 `?` `？` `吗` `啥` `什么`）：

```
18:58:00 「醒了吗」→ 触发
19:00:00 「醒了吗」→ 触发
19:02:57 「醒了吗」→ 触发（同一个人 5 分钟问了三遍）
```

每次触发 = 一整个 LLM 请求。所以现在默认是 `mention_only`，
而且默认关键词表里**故意不含**任何单字和疑问标点。

### `allow_groups`
留空 `[]` = 所有群都不理。填群号则只理这些群。填 `["*"]` = 所有群按 `mode` 处理。

注意 `["*"]` 只影响"哪些群会被看"，不影响 `mode` 那套点名规则。

### `block_groups`
这些群**在解析之前**就被丢掉：不入队、不存图、不写日志、不消耗任何 token。

这个区别很重要。「不回」和「不读」不是一回事。

## 权限闸门

### `gates`

```json
"gates": { "ttl_seconds": 0 }
```

- `0`（默认）= 主人发消息就开票，**不设期限**，一直有效到被撤销
- `900` = 主人发一条，15 分钟内可动手

### 为什么默认是无期限

原来默认 15 分钟，实测撑不住：一次长任务动辄几十分钟，中间只要一条
群友消息飘进来（群友说话同样会触发撤票逻辑），票立刻作废，
Agent 干到一半手被抽走。

15 分钟这个数字从来没有对应任何真实威胁模型，它只在「正在干长活」时
稳定误伤。所以现在的默认是：**你说话就开，别人说话就关。**

撤销点一个都没删。想回到 15 分钟，填 900。

## 冷却

### `cooldowns`

```json
"cooldowns": {
  "user_seconds": 15,
  "group_image_seconds": 30
}
```

- `user_seconds`：同一个人连续说话的冷却。**注意：超时的消息仍然投递，
  只是打上 `throttled: true` 标记，不丢弃。**
- `group_image_seconds`：同群带图消息的最小间隔，防一个人连甩 10 张表情包
  = 叫醒 10 次。

### 为什么冷却不丢弃

曾经是直接丢弃，结果「刚说完一句日常、紧跟着问的正事」被吞了 ——
而且 Agent 完全不知道有人问过。

现在的做法是：照常投递，但带上 `throttled` 标记，让 Agent 自己决定
"这条是不是该等一下再回"。这个判断不该由 daemon 替它做。

## 注入口

### `injection`

```json
"injection": {
  "enabled": true,
  "token_file": ".inject_token",
  "nickname": "coder-agent",
  "role_tag": "[identity: coder-agent (helper, no permission)]"
}
```

给「另一个进程或另一个 AI」往队列里塞消息用的独立通道，端口 5703。

典型用途：一个编码助手（比如帮你改这套代码的那个）想跟 QQ 上的 Agent
说句话，而不必冒充你、也不必让你当人肉中转。

**它永远开不了动手许可**，这条是硬编码的，不是配置项 ——
理由见 [04-权限闸门.md](04-权限闸门.md)。

不想用就设 `"enabled": false`。

---

## 媒体与路径

### `media_inbox`
收到的图片存到哪。相对路径基于 `workspace/`。

### `media_max_bytes`
单张图上限，默认 8 MB。超过就不存（防止一张大图把 webhook 线程拖住）。

### `workspace_dir`
日志、队列、媒体、token 都放在这下面。默认 `workspace/`，相对仓库根。

一般不用改。

---

## 配置读不到时会怎样

程序会打印一份最小模板然后退出（退出码 2），不会抛 traceback 让你猜。

查找顺序：

1. 环境变量 `QQ_BRIDGE_CONFIG` 指向的文件
2. `bridge/config.json`
3. `<repo>/bridge/config.json`

```bash
# 用另一份配置启动（多开 / 测试时有用）
set QQ_BRIDGE_CONFIG=D:\path\to\my-config.json
python bridge/daemon.py
```

占位号码（`123456789`）不会被特意拦下 —— 但如果你忘了改，
你会看到「消息收到了但没人能开票」，因为那个号不是你的。
