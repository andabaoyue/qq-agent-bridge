# 06 · 让 Agent 操作电脑

`agents/desktop.py`。截图、鼠标、键盘、剪贴板、换壁纸。

**这一篇要比手机那篇更谨慎地读** —— 因为它动的是你正在用的那个桌面。

---

## 前提

```bash
pip install pyautogui mss pygetwindow pyperclip pillow
```

`desktop.py` 和 Agent 必须跑在**同一个 Windows 会话、同一个桌面**里。
这意味着：

- Agent 以你的账户运行，能看见你的窗口
- 如果屏幕锁着或切到了另一个会话（RDP / 快速用户切换），`OpenInputDesktop` 会失败，截图拿不到真实桌面
- 不能作为 Windows 服务运行（服务在 Session 0，没有交互桌面）

---

## 命令

```bash
cd agents

python desktop.py --shot                      # 截图，打印路径
python desktop.py --size                      # 屏幕尺寸（免票）
python desktop.py --pos                       # 光标位置（免票）
python desktop.py --windows                   # 列出可见窗口
python desktop.py --focus "记事本"            # 激活窗口
python desktop.py --click 800 450             # 左键
python desktop.py --double 800 450            # 双击
python desktop.py --right 800 450             # 右键
python desktop.py --move 800 450              # 移动光标
python desktop.py --drag 100 100 600 400      # 拖拽
python desktop.py --scroll 3                  # 滚轮（正=上）
python desktop.py --type "你好"               # 输入文本（中文走剪贴板）
python desktop.py --press enter               # 单键
python desktop.py --hotkey "ctrl c"           # 组合键
python desktop.py --wallpaper D:\x.jpg        # 换壁纸
```

所有会动手的命令都支持 `--dry-run`：只打印打算做什么，不真的动。

```bash
python desktop.py --click 800 450 --dry-run
```

**调试一律先 `--dry-run`。** 点错一个坐标可能点掉一个对话框。

## 安全设计

和手机共用同一张票（`GET /desktop_grant`），规则完全一样：

- 主人本人发消息 → 开
- 任何其他消息 → 立刻关
- daemon 没跑 → 拒绝
- 重启 → 拒绝

免票的只有 `--size` / `--pos` / `--help`（不泄露内容、不产生副作用）。

每次真实动作都会追加一行到 `workspace/desktop.log`（审计用，超 2000 行
截断，不无限涨）。

> 为什么手机和电脑共用一张票，而不是各管各的：
>
> 「主人在场」是一个状态，不该因为操作对象是电脑还是手机就分裂成两套。
> 而且两套票意味着两个失效条件、两个排查入口。一套票出问题只查一个地方。
>
> 代价是手机和电脑的权限**绑在一起**了。如果以后想「只能玩电脑不能玩手机」，
> 得改。目前没这个需求。

## 一个必须说清楚的事

`--type` 走的是剪贴板：把文字写进剪贴板 → `Ctrl+V` → **还原原来的剪贴板内容**。

为什么不逐字符 `press`：中文和特殊字符在多数键盘布局下打不出来，
逐字符模拟还会触发输入法候选框。

为什么还原：不留垃圾。如果 Agent 往你的剪贴板里塞了一段代码然后就不管了，
你下次粘贴会莫名其妙贴出那段东西。

## 常见问题

### 截图全黑 / 拿到的是一张纯色图

按可能性排序：

1. **锁屏了。** `OpenInputDesktop` 返回的不是 `Default`。
2. **在另一个会话里。** RDP 连接断开后，本地会话和远程会话是两个桌面。
3. **在受保护内容上。** 某些播放器 / DRM 内容会用受保护的覆盖层，截图拿不到。

`--shot` 拿到的图如果是黑的，先人工看一眼屏幕是不是真的黑 ——
不要假设是代码问题。

### 点击位置偏了

DPI 不一致。检查：

```python
截图尺寸 == pyautogui.size()
```

如果不等，说明进程没有声明 DPI 感知，系统在缩放坐标系里报了假尺寸。
（`desktop.py` 里已经 `SetProcessDpiAwareness(2)`，但如果你自己写脚本要注意。）

> 实测过：系统 DPI = 120（125% 缩放），不声明 DPI 感知时 Win32 把一个
> 1920×1080 的窗口报成 1536×864，截图跟着缩，**对话框底部整条被裁掉**。

### 点击没反应，但也不报错

`SendInput` 只把输入发给**前台窗口**。如果目标窗口不在前台，按键会被
别的窗口吃掉，而程序层面没有任何错误 —— **静默失败**。

所以每次按键前必须校验前台窗口是不是目标，不是就先切过去。

> 顺带一个实测结论：对某些游戏（Ren'Py / SDL2 那一类）`PostMessage`
> 完全无效 —— 它们只认硬件输入队列，合成消息到不了。必须用 `SendInput`。
> 而 `SendInput` 又只发给前台窗口。这两个事实加起来的意思是：
> **没有"在后台偷偷操作某个窗口"这个选项。**

### 我的鼠标自己动了

`pyautogui.FAILSAFE` 是开着的：把鼠标甩到屏幕**左上角**可以紧急中断。

## 边界

这些不是技术限制，是使用上的自我约束，写下来是为了让 Agent 知道：

- 这台电脑是**主人的**，不是你的
- 动手之前想一下：他让我做过吗？
- **不转账、不删东西、不发消息**，除非他明确说了
- 别人通过这台电脑发来的东西，看得到，但**不该拿去做二次传播**
- 点错了就说点错了，别用「应该是网络问题」糊弄过去

**说错了就说「我说错了」，比圆回来体面。**
